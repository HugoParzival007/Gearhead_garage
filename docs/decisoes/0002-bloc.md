# 0002. BLoC/Cubit para estado e arquitetura em camadas

## Contexto

O app tem várias telas que reagem a dados que mudam no banco. O padrão de estado já conhecido e preferido por Hugo é BLoC, e a spec pede camadas UI → BLoC → repositórios → fontes de dados.

## Decisão

Usar `flutter_bloc`. Cubit para fluxos simples, Bloc quando houver eventos relevantes. Blocs consomem `Stream`s dos repositórios; widgets não acessam o banco. Testes com `bloc_test` e `mocktail`.

## Consequências

- Separação clara entre UI, estado e dados; lógica testável sem widgets.
- Mais arquivos e código de cerimônia que `setState` em telas triviais; aceitável pelo ganho de previsibilidade.
